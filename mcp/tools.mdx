The Oviond MCP server exposes **125 tools**. Most map to a single REST operation; a few chain
several. Tool names are verb-first — `create_client`, `list_reports`, `add_widgets` — so an agent
can guess the right one from the action.

Every tool also carries a title and read-only / destructive hints, so a client can show what a
tool will do before it runs. Tools marked 🔒 are destructive: a good client asks you before it
runs them.

## Conventions

- **Identifiers** — calls return IDs the agent chains into later calls. Clients, reports,
  templates, themes and widgets can also be passed **by name**. When a name matches several
  records, the call answers with the choices.
- **Multi-tenancy** — every call is scoped to the authenticated account. You never pass an
  `account_id`.
- **Discovery first** — `datasources`, then `describe_datasource`, before configuring a data
  widget: the second returns that datasource's data views, metrics, dimensions and required settings.
- **Metrics and dimensions are objects** — pass `[{ "value": "clicks" }]`, not `["clicks"]`. Only
  `value` is required; Oviond fills in the rest from the catalog. The same shape is used by the
  widget, goal and calculated-metric tools.
- **Widgets in bulk** — `add_widgets` adds many widgets in one call — a whole report at once —
  each with its own `page_id`, any of the 10 content types (title, text, image, button, embed,
  static value, data, calculated metric, goal, custom data). It places them on the page for you.
  `update_widgets` changes many at once; `move_widget` moves and resizes one. A wrong item is
  skipped with the reason; the rest are written.
- **Data is fetched server-side** after a widget is written. `add_widgets`, `update_widgets` and
  `refresh_widgets` wait up to 10 seconds and return a `data_check` with each widget's state and
  totals. `refresh_report` and `change_report_date_range` return at once. Reading the numbers back
  is `get_widget_data`.
- **`query_data` is the read-only way to pull figures.** It returns live metric values for any
  date range straight from the client's connected datasource and saves nothing, so it works on a
  read-only connection. Use `get_widget_data` to read what a report already holds, and
  `query_data` for ad-hoc analysis and period comparisons.
